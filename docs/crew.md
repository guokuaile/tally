# 刘海小人（小刻）

> 刘海两侧常驻的项目角色：一个项目一个黑玻璃小球，状态一眼看出谁在等你；悬停看项目和会话，点一下跳回终端。设置「面板」里可关。

## 边界

- 角色对应**工具 + 项目**（Claude 或 Codex 在某个规范化后的 `cwd` 目录里），不对应会话：同一家在同一目录的几条会话折成一个角色，球上不画会话数（数量在悬停卡片里）；同一目录两家都开着就是两个角色。已关闭的会话不进名册。
- 只在带刘海的内建屏上画，和面板同一条规则；面板展开、全屏隐藏、合盖只剩外接屏时两翼整个不上屏。
- 两翼是独立的 `NSPanel`（`CrewPanel`），不是刘海面板的一部分：刘海面板闭合态什么都不画（[panel.md](panel.md)「闭合态内容」），翅膀从物理刘海左右缘往里 12pt 起往外伸，接缝藏在面板底下。
- 不做：自定义形象、按会话而非项目聚合、拖动排序、外接屏上的角色。

## 状态表

一条会话先映射成一个 mood，一个项目取它所有会话里最急的那个（数字小的更急）；AI 页「失联」和这里用同一个 `isStale(now:)`（2 小时没更新且不是完成 / 已关闭）。

| mood | 会话状态 | 片段 | 看起来 | 静态帧时刻 |
|---|---|---|---|---|
| 0 permission | `waiting_permission` | `crew-permission` | 整个身体变成「!」2.4 秒，回球后瞪大眼睛抬头 1.6 秒；琥珀光晕 4 秒一次慢呼吸 | 1.6 s |
| 1 input | `waiting_input` | `crew-input` | 好奇脸带「?」，头慢慢歪到 9° 再回正（4 秒一轮，不抖），青色光晕同步慢呼吸 | 2.0 s |
| 2 compacting | `compacting` | `crew-compacting` | 炸成三个小玻璃球 2.6 秒再聚回 | 3.2 s |
| 3 run | `running`，或 `done` 但 `backgroundWork != nil`（主回合完了后台还在跑） | `crew-run` | 平视圆眼，3 秒一次环绕线；两次之间（0.7 到 2.1 秒）眼睛往右瞟一下再回正 | 0.9 s |
| 4 done | `done` 且没有后台工作 | `crew-done` | 缩成一点拖彗尾 2.4 秒，回球 3.6 秒：笑眼，描边闪一次绿再回流光；循环，一轮里六成时间球在格子里（回球 1.8 秒时格子有一半时间是空的，像没小人） | 3.0 s |
| 5 stale | `isStale(now:)`（判在最前） | `crew-stale` | 灰、眼皮半垂、视线下压、身体微倾；每轮 3 秒附近慢而重地合一次眼（0.3 秒），说明它还活着 | 0 s |

`ended` 不进名册；会话一关角色就没了。Codex 会话折不出 `input` / `compacting`，那是 hook 数据层的事实（[ai.md](ai.md)），名册不兜底。

mood 变了该槽的片段从头播。六个状态都循环自己的片段，完成没有另外的打盹片段：曾经「播一次绿环再合眼打盹」，用户看着和预览不一样、也像没动画，去掉了。

**等久了换档（`CrewTier`）**：等审批、等输入的角色再按等了多久分三档，取项目里等得最久的那条会话（`SessionRecord.waitingSince`，见 [ai.md](ai.md)「等你」）：不到 3 分钟是刚弹出，照状态表画；满 3 分钟光晕从琥珀 / 青转橙（`#FF8C1A`）；满 10 分钟换成失联的片段和灰配色（半合眼、灰身，就是落灰）但光晕转红（`#FF4D4D`；失联片段每帧光晕量是 0，这档的光晕量由样式定成 0.5、不呼吸）——真失联没有光晕，分得开。瞟一眼就知道哪个是被忘掉的，不用读计时器。档位和 mood 一起进片段缓存的键，变档和变 mood 一样从头播；名册每 60 秒重算一次，过线最多晚一分钟。别的 mood 恒为刚弹出那一档。不另画姿势：片段来自上游 bloub 的导出管线，换档只用现成的片段和颜色。

## 片段（`Resources/bloub/frames.json`）

六个 crew 片段和 AI 页的六个片段在同一份 `frames.json` 里（结构 `{clips: {名: {fps, frames}}}`），crew 片段 20 fps、老片段 30 fps，解码器按片段取 `fps`。采样脚本 `Resources/bloub/export.cjs`，上游 bloub 的提交钉在 `b4bb3c1`；几何变换（歪头、压扁、慢摆）和眼神（在跑的瞟眼）在导出时烘进坐标，原生端不做变换；在跑的环绕线和预览一样不缩（曾按 0.86 挤进 27pt 槽，线条太细），伸到约 ±137 单位即 15pt，31pt 槽内不探进邻座。每帧四个可空字段：`glow`（光晕不透明度）、`ring`（绿环不透明度）、`lids`（眼皮盖住比例）、`arcEyes`（眼睛画成弧线）；`dots` 里 `piece: true` 的点是身体分出去的碎片，按身体材质画（AI 页压缩中的三点也因此成了小玻璃球）。字段细节与重采样命令见 `Resources/bloub/README.md`；文件 ≤ 4.8 MB。解码时坏掉的小刻片段只丢那一段（翅膀发现缺片段就不画并记一条日志），AI 页的六个会话片段坏了才整份作废。

## 绘制与套系（`CrewStyle`）

`BloubArt.Frame.draw(in:time:style:)` 的 `style` 定色系与材质，绘制函数不认识片段：

- 配色照第 7 版预览按**表情**分，不按工具、目录或左右（`CrewStyle.palette(for:)`）：在跑 coral、等审批 peach、等输入 rose 是暖，压缩中 mint、完成 sky 是冷，失联 ash 灰。玻璃套系的描边只看冷暖，两套流光（`warmRim` 是 coral 那套的色环 `#FF7A3C → #FF487A → #FFB05C → #FFE078 → #FF6C54`，`coolRim` 是 AI 页那套蓝紫青）；每套的填色和眼皮色只给渐变套系。状态一变脸色跟着变，同一个项目没有固定的色。
- 套系 `glass`（默认）：近黑玻璃身体、流光描边、眼皮 `#1B1D24`；`gradient`：身体填该套系的上下两色渐变。
- 小尺寸档（`Style.small`，小刻一律开）：描边 9、光晕描边 26 模糊 9（AI 页 34pt 用大档 5 / 12 / 4）；绿环同一套粗细；轨道线按流光第 4 色到第 2 色渐变、线宽翻倍（22pt 球上 1.3pt，原来 0.6pt 像发丝）并垫一层模糊 6 的同色光，实心点取第 4 色，不是 AI 页固定的冷色。球身只有 22pt 时细描边看着像一根发丝，这是和预览最大的视觉差。
- `glow` 只有 permission（琥珀 `#FFC53D`）和 input（青 `#7DE3F7`）给色；`ring` 恒为品牌绿 `#60D880`；`opacity` 恒为 1（预览的失联不半透明）；`compactSymbol` 只在 input 为真（帧里的「?」符号只给小刻画，AI 页不传 style 就不画）。

## 名册（`CrewRoster`，纯函数）

- 项目键：`<工具>:<目录>`。工具只认 claude / codex（别的值按 Claude 算，和 `providerLabel` 一致）；目录是 `cwd` 经 `NSString.standardizingPath` 去 `.`、`..`、多余和结尾斜杠，再由调用方解符号链接（`CrewController` 传 `resolvingSymlinksInPath`）；名字取最后一段，根目录是 `/`。
- 排序：mood 升序；等审批、等输入的项目按开始等的时刻正序（等得最久的最靠刘海，和 AI 页等你组、⌘1 一致：被忘掉的那条才该最显眼），其余 mood 按最近 `updatedAt` 倒序。
- 槽位（浮动交界）：两家都在用时 Claude 一块在左、Codex 一块在右，两块相邻；各家都不超过 `perSide` 时交界就是刘海（3 + 3 就是左三个 Claude、右三个 Codex），一家超过就把交界往对面推，多出来的占对面翼贴刘海的格（5 Claude + 1 Codex：左翼三个 Claude，右翼贴刘海两格也是 Claude，Codex 在右翼最外）。每块里按离刘海由近到远放最急到最闲，同距先放自己那边。只用一家时不分边，按急缓围着刘海左右交替（最急的在右翼贴刘海那格，第二急的在左翼贴刘海那格，之后右、左、右、左）。
- 溢出：项目数超过 `2 × perSide` 时按急缓砍最闲的（不分工具），只显示前 `2 × perSide − 1` 个，空出的那一翼最外格换成「+N」胶囊（`CrewLayout.overflowSide`；只用一家时固定在左翼），N = 项目数 − (2 × perSide − 1)，连被胶囊顶掉的那一个一起数。翼宽按实际占用算，不按 `perSide`。
- 新会话（工牌用）：按提供方和会话 id 判断，只有启动 10 秒之后首次出现的会话进工牌；同项目的新会话也发，刷新同一会话不重复。启动和工牌开关重开时的首份快照只记不发。

## 翅膀（`CrewGeometry` + `CrewPanel`）

| 量 | 值 |
|---|---|
| 槽宽 / 球身 / 翼内边距 | 31 / 22 / 8pt；翼宽 = 12 + 8 + 各格宽度之和 + 8，悬停不改变翼宽，相邻槽的点击区之间留 4pt 空隙（鼠标与辅助功能一致）；靠刘海那头的 12pt 伸到物理刘海底下 |
| 翼高 / y | `safeAreaTop` / `frame.maxY − safeAreaTop`，和闭合态面板同高同顶 |
| 右翼 x | `frame.maxX − auxiliaryTopRightWidth − 12`（从物理刘海右缘往里 12pt 起）；14 寸 3 格 = (836, 950, 121, 32) |
| 左翼 | `maxX = auxiliaryTopLeftWidth + 12`（到物理刘海左缘往里 12pt 止）；14 寸 3 格 = (554, 950, 121, 32) |
| 球心 | 离翼顶 19pt，翼内 x = 12 + 8 + 前面各格宽度之和 + 15.5，从靠刘海那一侧数起；下拉卡片锚在角色正下方 |
| 形状 | 纯黑，外侧底角圆角 12，内侧直角。物理刘海的底角是圆的，闭合面板的底角（半径 12）也跟着圆：翼要是只贴到刘海边，两段圆弧之间就露一条缝，所以翼往刘海底下多伸 12pt 把那块填黑（面板级别更高，盖在翼上，接缝看不出来） |
| 窗口 | 属性照提示药丸（非激活、无阴影、`canJoinAllSpaces` 等），级别 `.mainMenu + 2`：比刘海面板（+3）低、比菜单栏和状态项高 |

**画法**：一格一个 `CALayer`，内容是预先画好的位图（`CrewFrameCache`，键 = 片段 · 帧号 · mood · 套系，48 × 32pt @2x，一帧一张懒画、名册换了把不在屏上的那几套扔掉）。20 fps 的 `Timer` 每 tick 算每格该是哪一帧、变了才换 `contents`。原来用 SwiftUI `Canvas` + `TimelineView` 每 tick 重画六个角色，真机 13% CPU（AttributeGraph 占大头），换成位图后六个角色 ≤ 3%。

**时钟**：只在两翼真的在屏上且该动时走；系统减少动态效果时停表、每格取状态表里的静态帧；屏幕熄灭到点亮、登录会话不活跃期间停；低电量模式放到 10 fps。失联要按时间翻，所以每 60 秒重算一次名册。

**接入点**（`NotchController`）：`sessionsChanged` → `crew.refresh`；`relayout` → `crew.relayout(metrics:)`（没有刘海屏传 nil，两翼撤下）；`evaluateFullScreen` / `relayout` → `syncCrewVisibility()`；`open()` 立刻藏两翼，`close()` 等收起动画走完 0.32 秒再放回来；`applyPreferences` 同步 `sharingType` 与三个偏好键；`NotchPanel.steppingAside` 把 `CrewPanel` 一起压到 `.normal`。

## 悬停下拉与点击（`CrewExpand`）

- 光标进入角色 150 ms 后，原槽角色由透明且不拦鼠标的覆盖层接力，从原坐标连续移动到下方列表头部，沿原状态与样式显示；列表向外侧延伸，其他角色位置不变。减少动态效果直接显示目标帧。两翼宽度不变，下拉顶部与角色翼保留间隔，避免遮盖相邻角色的光晕。列表标题为目录名加「项目组」；每行用状态图标、状态文字、标题和模型区分各会话，等待时显示可用的审批摘要，在跑或完成时显示本回合最近工具动作；没有动作时完成显示消息摘要，点击具体行跳回对应终端。列表过长可滚动；悬停进入列表不收，离开角色和列表 300 ms 后收。列表临时显示在提示药丸前面，不清除药丸。项目位置或内容变化时跟着更新，项目消失、面板展开、全屏隐藏、屏幕变化或开关关闭时收起；截屏隐藏和系统模态窗口让路沿用刘海面板规则。
- 直接点击单会话角色仍跳终端；下拉后只有一个会话时，点击探出的角色或项目头部也跳同一终端。多会话角色和「+N」直接点仍打开 AI 页；下拉列表的各行分别跳对应会话。下拉列表的行是可访问性按钮，不依赖颜色判状态。

## 工牌（`Peek.style = .badge`）

工牌和小人分别开关；工牌设置可控制停留秒数、刘海左侧或右侧挂点及卡片左上角的自定义名称（默认「员工证」）。挂点贴近刘海边缘，卡片略倾斜并摆入。会话首次出现显示「已入职」，从已关闭恢复显示「已返聘」，从活跃变为已关闭显示「已离职」；普通回合完成后继续运行不算返聘。工牌关闭时清除已排队和显示中的工牌，重新开启时先记录当前会话，不补发。关闭小人不影响工牌。

刘海边缘垂出浅色工牌：两条印有 Tally 的挂带连接卡片，整张工牌从挂点摆入并回到微斜的位置。卡片显示动态小刻肖像、按会话稳定选出的花名和头像配色，以及部门（目录名加「项目组」）、岗位（应用及模型）；喜欢、不喜欢、口头禅、小秘密用语意完整、标点自然的幽默短句，结合网络梗与典故，默认从通用文案中选；设置可额外多选开发、写作、设计、数据主题，通用池始终参与且每项至少占一半选择权，不猜会话职业。花名和四类文案按会话 ID 加字段标识稳定选择（不调用模型、不额外存盘）；主题组合不变时入职、返聘和离职保持一致，修改主题后可能重新分配，随后大号印章以放大回弹的方式倾斜盖在肖像右下偏中位置，透明底配彩色文字与方角双层边框，空白处透出肖像与工牌，入职和返聘为朱红、离职为灰蓝；底部装饰条码加高，线条与间隔粗细不等。肖像复用在跑片段，仅在工牌可见期间播放；离职肖像及其底色去饱和。六项资料的字段名始终显示，字段值依次从左向右逐字出现，约 1.6 秒内全部显示；完整文字预留排版空间，避免工牌抖动；减少动态效果时直接显示静态文字和肖像。工牌只在可见卡片和挂带内接收点击，入场约 1.5 秒为摆动留额外命中范围，结束后收紧；鼠标位置的监视仅在交互式工牌可见期间存在。工牌使用独立高度，队列根据内建屏可用高度限制同时展示的提示，放不下的排队；屏幕变小时尾部放不下的提示回队列。入职和返聘点击按「点提示条时」设置处理并指向会话；离职不可点击。过期与去重规则不变。

发牌的是 `NotchController` 观察会话快照：第一份快照整个记住不发（启动、工牌开关关掉再打开都算第一份），启动前 10 秒的变化只记不发。`SessionStore` 把确认关闭但不保留的记录也交给工牌判断；会话未生成 transcript 就结束时，hook 将状态文件原子移为带唯一标识的一次性 `.tally-end` 文件，读取后删除；同一会话已重新出现时忽略旧结束记录，不加入已关闭列表；短暂读不到记录不算离职。进程内保留最多 500 条已消失的会话身份，超过或重启后无法识别早先已清理的会话为返聘。面板展开或全屏隐藏期间出现的会话不补发；工牌依次显示，普通提示不挤走挂点。

## 设置

设置窗口「AI 会话」→「刘海小人 / 会话工牌」：

| 键 | 默认 | 含义 |
|---|---|---|
| `crewEnabled` | `true` | 刘海两侧显示项目小人；关掉两翼 `orderOut`、时钟停，工牌不受影响 |
| `crewPerSide` | 3 | 每侧最多几个（1–4，超出夹住） |
| `crewSkin` | `glass` | `glass` 黑玻璃 / `gradient` 渐变；别的值回落 `glass` |
| `badgeEnabled` / `badgeSeconds` | `true` / 8 | 工牌开关与停留秒数（2–30） |
| `badgePosition` / `badgeTitle` | `right` / 员工证 | 刘海左 / 右挂点与自定义名称 |
| `badgeThemes` | `[]` | 可多选 `development` / `writing` / `design` / `data`，通用池始终参与；旧设置默认无额外主题 |

## 演示模式

`--demo` 的会话固定六个项目恰好覆盖六个 mood（Claude：shop-web 等审批 12 分钟、infra 等输入 4 分钟、api-server 压缩中；Codex：mobile-app 在跑且有两条会话、payments 完成、docs-site 失联）加两条已关闭，默认 3 + 3 正好放满；两条等你的正好一档一个：shop-web 落灰（灰身红光晕），infra 橙光晕；`--demo --crew-overflow` 多两个在跑的项目（8 个），Claude 四个把交界推过刘海，右翼最外是「+3」。`--demo --peek-test` 第 0.5 秒注入一张工牌（直接注入，不经 10 秒规则）。
