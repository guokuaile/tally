# 独立药丸提示

## 问题

现在提示条与刘海共用一个面板，显示提示时刘海壳跟着变宽、变高；同一时刻只显示一条，待显示区也只留一条，多条事件容易看不到。用户希望药丸与刘海分开，并能同时看见多条提示。

目标用户是本机的 Tally 使用者。目标是同时阅读和操作提示，且每条展示足够时间。按用户选定的刘海下方纵向叠放设计；没有刘海的屏幕仍走系统通知。验收时要能在不调整刘海闭合尺寸的前提下同时看到多条、逐条点击、验证显示时长和溢出排队。

## 不做什么

不修改 Ghostty / Codex 会话定位算法、不改变现有提示来源或设置项；仅演示模式新增 `--peek-test` 注入固定假事件、不新增服务或第三方依赖、不为提示条申请新的系统权限、不改真实会话文件。会话的准确跳转属于独立问题，不得以药丸改造声称已经修复。

## 方案选型

- **每条药丸独立面板、纵向排列（推荐）**：原刘海面板保持闭合尺寸；每条提示使用自己大小的透明面板，放在刘海下方。面板之间的间隙没有窗口，因此鼠标可直接穿过。代价是要管理多个短寿命窗口的显示、隐藏、层级、全屏、捕获保护和鼠标命中。
- 继续把提示画在刘海面板，但改成透明壳和胶囊背景：窗口 frame 仍须随提示改变，并与面板原有鼠标追踪及展开逻辑耦合；不满足刘海面板尺寸不动的要求。
- 系统通知：已有无刘海屏的退路；样式、同时展示与停留时长由系统决定，无法满足当前交互。

## 设计

### 展示和队列

最多同时展示三条，置于刘海下方并垂直居中对齐。会话药丸宽度取 `min(320pt, 内建屏宽 − 32pt)`，左右至少各留 16pt，比原 370pt 预览略小；单条高度 44pt。第二行目录与标题分开排版，目录最多占内容区 40%，长目录从中间截断，其余空间给对话标题并从中间截断。左侧复用 AI 会话列表的 `SessionEyes` 动画；第一行依次是提供方图标、模型和状态，状态文字按状态着色（完成绿、等审批 / 输入提醒色）；第二行是目录和对话标题。会话事件生成药丸时从 `SessionRecord` 快照 provider、modelLabel、state、cwdLabel 与 displayTitle；之后会话消失也不影响当条文案，点击仍按 sessionId 查询当前可跳转对象。还不知道模型时显示提供方名；非会话提示保留原有图标和内容。超过三条在内存等待，不抢占当前可见提示。每条可见提示从实际显示时开始独立计时：完成提示、配额和更新使用现有会话停留设置，等待审批 / 输入额外 3 秒，电池与文件架使用电池停留设置；等待中的条目不计时。同一个会话的后续状态替换当前或等待中的旧条目，并按新状态重新计时。不同会话各自保留，等你类优先于完成，其余按既有优先级排序，同级按到达顺序；等待区按会话 ID 和配额窗口分别去重，最新状态替换旧状态。正在等待审批 / 输入的会话只在仍处于等待状态时保留在待显示区，最多一条对应一个当前会话；状态改变或会话消失时取消该条，当前活跃会话数决定这一类上限。其他事件的详细待显示项最多 30 条；超过容量或等待超过 60 秒时，按类别合并为计数摘要并明确显示“详情已过期”，原事件文字和点击目标不再保留。摘要按 AI 完成、配额、电池、文件架、更新分别计数和指向 AI、AI、系统、文件架、设置；同类摘要只保留一条。摘要不占 30 条详细提示名额；如果目标页当前不可用，摘要仅显示不提供点击。这个淘汰规则意味着摘要不能还原每条历史内容，须在实施前明确确认。排队时优先展示等待审批 / 输入；其他按既有优先级排序，同级按到达顺序。队列只在可见位置空出时选择，现有药丸不被抢占。

会话药丸点击沿用设置的三种动作；只跳终端时仅关闭被点击的条目，其余可见及等待提示继续按各自计时。若动作包含展开 AI 页，以展开面板清除所有提示的规则为准。不可点击的类型不拦截其内容区域以外的鼠标。多条里即使一条定位失败，也不影响其他条目。展开主面板时清除全部可见及等待提示，取消所有提示计时；收起主面板后不会恢复已清除的旧提示。

### 窗口和系统行为

刘海面板在闭合时始终使用现有闭合尺寸，每条药丸使用独立透明、非激活面板，面板大小与胶囊外接矩形相同；面板外包括药丸之间的间隙均不拦截鼠标，圆角内仍按矩形接收点击。首次点击应生效，不抢键盘焦点。每个提示面板接入 `NotchController.evaluateFullScreen`、`relayout`、`applyPreferences` 和 `NotchPanel.steppingAside`，与刘海面板共用全屏隐藏、屏幕变化、截屏隐藏和模态让路规则；合盖或无刘海屏时会话 / 配额 / 文件架仍走现有系统通知。关闭或切换空间不能留下孤儿窗口。减少动态效果时保持静态。提示不会因为鼠标悬停而提前消失，独立计时器过期只影响对应条目。

## 预算与停止

连续 20 分钟没有新证据或同一路径失败两次时报告并重新确定方案；规格复审三轮仍有阻断项则回到方案选型。超过三条必须排队；超过等待区容量或等待时限时通过合并计数明确提示。

## Review Focus

1. 多条到期、替换、点击与展开并发时，不能误删别的提示或复活过期提示。
2. 提示面板的透明区域、焦点、全屏空间与系统模态窗口不得影响原面板交互。
3. 无刘海屏、合盖、重连、屏幕共享隐藏不得漏提醒或暴露受保护的内容。
4. 等待区溢出必须有可观察的明确处理，过期或合并时必须如实说明详情不可恢复。
5. 会话跳转尚不能可靠定位时，提示点击不得跳往另一个会话。

## 影响面

涉及 `NotchController`、`NotchPanel`、提示视图和几何计算、队列测试、`docs/panel.md`；会话数据及 hook 文件契约不变。回滚方式是恢复对应应用代码和文档并重新安装；不迁移数据。视觉草图是临时探针，不能当作实现或真机交互验收。
